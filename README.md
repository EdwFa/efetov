# Система поддержки клинического исследования

Прототип CRF-системы для многоцентрового исследования колоректального рака: журнал пациентов, карточка из пяти блоков, файлы, аудит, выгрузки Excel/CSV.

Это рабочий React-порт HTML-прототипа из `TZ/`. Данные хранятся в SQLite через FastAPI, без Docker.

## Стек

| Слой | Технологии |
| --- | --- |
| UI | Vite 6, React 19, TypeScript, React Router 7, Tailwind CSS 3 |
| API | FastAPI, SQLAlchemy 2, Uvicorn |
| БД | SQLite, файл `backend/data/efetov.db` |
| Сессия | JWT (HS256), пароли — PBKDF2-хеш |

В браузере остаются только `efetovSessionUser` и `efetovToken`. Пациенты, файлы и аудит живут в SQLite.

## Запуск

Нужны Node.js 18+, npm и Python 3.11+. Два процесса: API на порту **8000** и UI на **3000**.

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
pip install -r backend/requirements.txt
npm install
```

macOS / Linux:

```bash
source .venv/bin/activate
pip install -r backend/requirements.txt
npm install
```

Дальше в двух терминалах (venv должен быть активен в том, где запускается API):

```bash
npm run api
npm start
```

UI: [http://localhost:3000](http://localhost:3000)  
API: [http://127.0.0.1:8000](http://127.0.0.1:8000) · проверка `GET /api/health`

Файл БД создаётся сам при первом старте API и заполняется из `backend/seed.json`. В git он не входит. Кнопка **«Сбросить демо-данные»** в шапке перезаписывает SQLite этим же seed.

| Команда | Назначение |
| --- | --- |
| `npm run api` | FastAPI + SQLite, порт 8000, с reload |
| `npm start` / `npm run dev` | Vite, порт 3000 |
| `npm run build` | проверка TypeScript и сборка UI в `dist/` |
| `npm run start:prod` | один процесс: API + собранный UI, порт 8000 |
| `npm run preview` | просмотр собранного `dist/` без API |

Секрет JWT задаётся переменной `EFETOV_JWT_SECRET` (для демо есть значение по умолчанию). На сервере его нужно сменить.

Чтобы пересобрать `backend/seed.json` из фронтенд-сида:

```bash
npx tsx scripts/export-seed.ts
```

## Деплой на сервер (без Docker)

На облачной ВМ UI и API работают с одного порта: сначала `npm run build`, затем FastAPI отдаёт `dist/` и `/api`. SQLite держите на диске, который не стирается при перезапуске.

```bash
git clone https://github.com/EdwFa/efetov.git
cd efetov

python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt

npm ci
npm run build

export EFETOV_JWT_SECRET='длинный-случайный-секрет'
export EFETOV_CORS_ORIGINS='https://ваш-домен'
# export EFETOV_DATA_DIR=/var/lib/efetov

npm run start:prod
```

Проверка: `http://СЕРВЕР:8000/api/health` и `http://СЕРВЕР:8000/`. Снаружи обычно ставят nginx/Caddy на 443 и проксируют на `127.0.0.1:8000`.

Переменные — в `.env.example`. Файл `.env` в репозиторий не коммитится.

## Что умеет прототип

- **Вход и сессия.** После логина возврат на исходный URL. Выход по кнопке. Автовыход через 15 минут бездействия (кнопка **«Timeout 15 мин»** имитирует то же событие). Оба варианта пишутся в аудит.
- **Общий журнал.** Фильтры, сортировка, создание и удаление карт (по роли), колонка блокировки.
- **Карточка пациента.** Пять блоков CRF. Неполный seed дополняется полной схемой полей; неизвестные поля не теряются. ИМТ считается из роста и веса.
- **Блокировка.** Карту можно взять в работу. Чужой lock делает поля только для чтения; руководитель может снять блокировку или перехватить её. Сохранение через API отклоняется, пока карту держит другой пользователь.
- **Файлы.** Общее демо-хранилище с папками по месяцам и ролям (без реальных бинарников).
- **Аудит.** Неизменяемый журнал действий, только для руководителя.
- **Выгрузки.** Итоговая Excel-таблица по шаблону заголовков и статистический срез с учётом фильтров журнала. CSV — дополнительная опция. Колонки заполняются по точному заголовку поля. Персональные поля (ФИО, телефоны, адрес) в выгрузку не попадают.

## Права по ролям

| | Стационар | Амбулатория | Руководитель |
| --- | :---: | :---: | :---: |
| Журнал, просмотр карт | да | да | да |
| Создание карты | да | нет | да |
| Удаление карты | нет | нет | да |
| CRF: общие / анамнез / предоперация / операция | просмотр и правка | просмотр общих и анамнеза | всё |
| CRF: послеоперационные наблюдения | нет | просмотр и правка | всё |
| Файлы: скачивание | да | да | да |
| Файлы: загрузка / удаление | нет | нет | да |
| Аудит и Excel-выгрузки | нет | нет | да |

Если руководитель правит карту, созданную другим пользователем, система запрашивает подтверждение. Матрица прав дублируется на клиенте (кнопки) и на сервере (отказ 403).

## Как устроены данные

SQLite-файл: `backend/data/efetov.db`.

| Таблица | Содержимое |
| --- | --- |
| `users` | логин, PBKDF2-хеш, роль |
| `patients` | реквизиты карты; блоки CRF в `blocks_json` |
| `files` | метаданные демо-файлов |
| `audit_events` | журнал действий |

Клиент в dev ходит на `http://127.0.0.1:8000/api`. Vite также проксирует `/api` на тот же адрес, если открывать относительные URL.

Основные эндпоинты: `POST /api/login`, `GET /api/runtime`, CRUD пациентов, lock/unlock, файлы, аудит экспорта, `POST /api/reset-demo`.

## Структура репозитория

```
backend/
  app/              FastAPI: модели, RBAC, CRF-merge, REST
  seed.json         сид БД
  data/efetov.db    SQLite (локально, не в git)
src/
  app/              маршруты, оболочка, idle-timeout
  pages/            тонкие экраны
  features/         журнал, карточка, файлы, аудит, экспорт, auth
  entities/         роли, CRF-схема, пациент, файлы, аудит
  api/              HTTP-клиент (`http.ts`)
  shared/           UI-кит, даты, выгрузки
scripts/export-seed.ts
TZ/                 исходный HTML-прототип и постановка
```

Ключевое:

- `backend/app/` — модели, права, seed, REST
- `entities/user/roles.ts` — матрица прав на клиенте
- `entities/crf/schema.ts` — ключи полей и заголовки Excel
- `api/http.ts` — JWT и вызовы API
- `api/mock/seed.ts` — шаблон Excel; `backend/seed.json` — сид БД

Папка `TZ/` — UX-референс и постановка, в `src` не подмешивается. Старый прототип: открыть `TZ/index.html` в браузере.

## Ограничения

Это кликабельный прототип, не промышленная система: нет требований 152-ФЗ, объектного хранилища файлов, миграций Alembic и выноса на общий сервер для нескольких центров. Открытые вопросы к заказчику — в `TZ/Вопросы_к_Заказчику.md`.
